# یافته قطعی ۱ — معماری شش‌لایه و اصول طراحی

**وضعیت:** قطعی (در هر دو خانواده منبع مشترک)
**منابع:** خانواده A (بخش ۲) · خانواده B (بخش ۲)

## معماری شش‌لایه

| لایه | نام | وظیفه |
|---|---|---|
| ۱ | منابع و دروازه‌ها | دریافت داده از نهادهای آمار، پیمایش، رسانه، GIS و گزارش میدانی |
| ۲ | ذخیره خام (raw) | ثبت تغییرناپذیر (immutable) داده ورودی با timestamp و hash |
| ۳ | پاک‌سازی و هوشمندسازی | اعتبارسنجی، یکسان‌سازی واحد، تطبیق نام مکان، NLP فارسی |
| ۴ | پایگاه داده موضوعی–مکانی | جداول ref/core با PostGIS و مدل زمانِ دومرگ |
| ۵ | انبار داده + محاسبه شاخص‌ها | تجمیع bottom-up، محاسبه شاخص ترکیبی، سناریو |
| ۶ | سرویس‌های نقشه + API + داشبورد | سرویس OGC، داشبورد سه‌سطحی، هشدار و گزارش |

## اصول قطعی

1. **مرجع واحد (Single Source of Truth):** هر مشاهده به یک `region_id` و (در اماکن) یک `facility_id` منحصربه‌فرد متصل است؛ ثبت بدون کد مکان ممنوع.
2. **مدل زمان دومرگ (bi-temporal):** ستون‌های `valid_from/valid_to` (اعتبار تاریخی) جدا از `recorded_from/recorded_to` (اعتبار ثبتی). تغییر مرزها (ارتقا/الاحاق/تفکیک) با `valid_from/valid_to` ثبت می‌شود تا سری زمانی در برابر تغییر مرز خطا نگیرد.
3. **فاصله‌بندی نیمه‌باز:** بازه‌ها به‌صورت [آغاز، پایان) تعریف می‌شوند.
4. **جدول رابطه‌ی مستقل مکان:** شهر/بخش درخت ساده نیست؛ `geo_relation` با `relation_type` و بازه اعتبار.
5. **جداکردن طبقه داده:** observed/registered · survey_estimate · modeled · scenario · qualitative.
6. **حاکمیت داده:** برای هر شاخص سه نقش مشخص — مالک داده (data owner)، متولی فنی، مسئول داده مکانی.
7. **پایان‌بندی:** عبور از «بانک اطلاعات آماری» به «سامانه پشتیبان تصمیم آمایش سرزمین» (رصد + آشکارسازی نابرابری + سناریو + تناسب کاربری با توان سرزمین).
